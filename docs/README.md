# 설계 문서

MySQL 기반 비회원 게시판의 데이터 구조와 서비스 처리 계약을 분리해 관리한다. 이 문서는 API·워커 구현이나 DB 제약 설치를 의미하지 않는다.

| [저장 정책](storage-policy.md) | MySQL 엔진·문자셋·collation·UTC·DDL 적용 경계 |

## 읽는 순서

1. 데이터 모델에서 정본과 논리 관계·논리 키·증거 복사를 구분한다. 모든 관계는 물리 FK가 없다.
2. 저장 정책·관계 무결성과 필요한 도메인의 처리 설계를 읽는다.
3. 조회 계약과 JSON 데이터 계약에서 세부 입력·출력 조건을 확인한다.

## 변경 원칙

테이블 선언과 구조 요약은 `prisma/schema.prisma`가 정본이며 `erd.md`를 직접 수정하지 않는다. 상세 계약은 해당 `docs/` 파일에만 작성하고 링크로 연결한다. 변경 이력·배포 가정·검증 실행 기록은 설계 본문에 넣지 않는다.
