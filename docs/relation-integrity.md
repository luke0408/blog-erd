# 논리 관계와 서비스 무결성

관련 구조: [ERD](../erd.md). 물리 FK 없이 관계를 유지하는 서비스 계약이며, 검증 API·정리 배치가 구현되었다는 의미는 아니다.

## 책임 경계

모든 테이블에 물리 FOREIGN KEY를 설정하지 않는다. PK·UNIQUE·NOT NULL·명시적 인덱스는 유지한다. ERD의 관계선과 Prisma `@relation`은 논리 관계를 표현하며 DB가 참조 행의 존재나 소유자 일치를 강제한다는 뜻이 아니다.

| 계층 | 책임 |
| --- | --- |
| DB | 선언된 기본 키·중복·NULL 제약과 트랜잭션·잠금 |
| 비즈니스 서비스 | 참조 존재·소유자·상태·권한·불변성·생성 완결성·삭제 정책 |
| 운영 정리·점검 | 같은 검증 계약 적용, 고아 데이터 탐지와 승인된 보존 정책 수행 |

`relationMode = "prisma"`는 FK 생성 없이 ORM 관계를 유지한다. `onDelete`·`onUpdate`는 `NoAction`으로 선언하며 Cascade·SetNull에 의한 자동 삭제·연결 해제를 사용하지 않는다. Prisma Client의 일부 관계 검사는 보조 수단일 뿐이다. 생성 시 참조 무결성 검사와 원시 SQL에는 관계 에뮬레이션이 적용되지 않으므로, 어떤 쓰기 경로도 서비스 검증을 생략하지 않는다. ORM 경로에서 관계 오류가 발생할 수 있어 임의의 삭제가 항상 성공한다는 의미도 아니다. [Prisma 관계 모드](https://docs.prisma.io/docs/orm/v6/prisma-schema/data-model/relations/relation-mode)

물리 FK 부재는 운영 정책의 소유권을 서비스로 옮기는 선택이다. 성능 개선은 자동으로 보장되지 않는다. 관계 검증 쿼리·인덱스·잠금과 ORM 에뮬레이션 비용까지 포함해 CUD 지연과 경합을 측정한다.

## 참조별 검증 계약

| 참조 | 생성·변경 시 서비스 검증 |
| --- | --- |
| User.browserCredentialId | 연결 시 키 존재·비밀 소유·고정 만료·철회·PREFERENCES 범위 확인, PERSONAL 환경만 허용 |
| GuestIdentification.userId | 판정 소유 방문 존재, 해당 요청의 유효 세션 또는 같은 트랜잭션에서 발급한 방문 |
| GuestIdentification.browserCredentialId | 연결 시 유효 키이며 해당 User의 바인딩과 일치 |
| GuestIdentification.networkClassificationId | 판정 시 유효 캐시, 환경 일치와 서버 증거 복사; 이후 캐시 갱신으로 과거 증거를 재검증·수정하지 않음 |
| Post.authorId·Comment.authorId | 생성 시 유효 작성 방문 존재, 이후 최초 작성자는 불변 |
| PostSnapshot.postId·CommentSnapshot.commentId | 소유 콘텐츠 존재, 같은 콘텐츠 잠금 아래 다음 revision 생성 |
| Post.currentSnapshotId·Comment.currentSnapshotId | 스냅샷 존재·소유 ID 일치·최대 revision, 완료된 생성에는 최소 정본과 포인터 필수 |
| Comment.postId | 소속 포스트 존재·쓰기 허용 상태, 생성 후 변경 금지 |
| Comment.parentId | 부모 존재·같은 postId·자기 부모 금지·생성 후 변경 금지, 순환 구조 거부 |

선택적 참조는 NULL을 허용하지만, 값이 있으면 생성 시 검증한다. 존재 확인만으로 인증이나 콘텐츠 관리 권한을 인정하지 않는다. 상세 권한은 [비회원 세션](guest-session.md)과 [콘텐츠 수명주기](content-lifecycle.md)를 따른다.

Report의 대상·작성자·신고자·스냅샷 키와 저장된 editorKey는 역사적 식별 정보다. 신고 수락·정본 생성 시 필요한 실제 대상과 권한을 검증하되, 이후 원본의 존재를 영구적인 필수 조건으로 두지 않는다. EventReceipt의 외부 eventId도 로컬 OutboxEvent 존재를 요구하지 않는다. 이 키들은 Prisma 관계선이 아닌 [증거 복사](report-moderation.md)·[이벤트 계약](event-processing.md)에 속한다.

## 동시성 계약

트랜잭션 밖에서 존재를 확인한 뒤 INSERT하는 방식만으로는 삭제와의 경합을 막을 수 없다. 참조를 추가하는 경로와 부모를 삭제·철회하는 경로 모두 같은 부모 행의 잠금 규약을 사용한다.

1. 필요한 인증·외부 분류를 처리하고 짧은 DB 트랜잭션을 시작한다. 외부 호출은 트랜잭션 안에서 하지 않는다.
2. 참조할 부모와 변경할 콘텐츠 루트를 정해진 순서로 잠근다. 같은 행 잠금은 생성·변경·정리 작업 모두 공유한다.
3. 잠금 후 참조 존재·소유자·허용 상태·만료·권한을 재검증한다. 삭제된 부모나 철회된 세션이면 거부한다.
4. 정본·포인터·메타데이터·OutboxEvent를 함께 저장하고 커밋 전 완결성을 확인한다. 실패는 전체 롤백한다.

잠금 순서는 서비스 간 공통으로 User → GuestBrowserCredential → NetworkClassification → Post → Comment → 해당 Snapshot으로 고정하며, 같은 종류에서는 ID 오름차순을 사용한다. 필요한 행만 잠그고 관리 키·판정 기록의 권한 검증을 잠금으로 대신하지 않는다. 관계 탐색으로 ID를 먼저 조회했다면 잠금 후 바인딩을 다시 확인한다. 삭제 경로에서 역참조를 발견해 앞선 종류의 잠금이 추가로 필요하면 현재 트랜잭션을 종료하고 전체 잠금 집합으로 다시 시작한다.

스냅샷 revision과 currentSnapshot 변경은 같은 콘텐츠 루트 잠금 및 expectedVersion 비교를 사용한다. 중복은 UNIQUE로 최종 차단하며, 교착·일시 오류는 횟수가 제한된 재시도와 기존 멱등 키를 사용한다. 상태 불일치·권한 실패·버전 충돌은 자동 덮어쓰지 않는다.

부모 삭제는 먼저 같은 잠금 아래 신규 참조 가능 여부와 기존 역참조를 확인한다. 자식 확인 쿼리도 최신 커밋을 보는 잠금 읽기를 사용하고, 오래된 일반 조회 결과를 삭제 근거로 사용하지 않는다. 관리자 도구·원시 SQL·운영 스크립트가 이 규약을 우회하면 물리 FK 없이 정합성을 보장할 수 없다.

## 삭제와 보존

| 대상 | 삭제 정책 |
| --- | --- |
| Post·Comment | 일반 삭제는 DELETED 상태 전환; 메타데이터·정본·신고·이미지 보존, 연쇄 물리 삭제 금지 |
| User | 세션 만료·철회는 행 삭제가 아님; 작성 콘텐츠·판정 등 유지할 필수 역참조가 있으면 물리 삭제 거부 |
| GuestBrowserCredential | 미만료·미철회 키 삭제 금지; User·판정 역참조가 남으면 물리 삭제 거부 |
| NetworkClassification | 만료 캐시는 재사용 금지; 판정 역참조가 남으면 물리 삭제 거부 |
| GuestIdentification | 보존 만료 후 정리 가능; 증거 UPDATE·타 방문 재연결 금지 |
| Snapshot·Report | 증거 보존 정책 우선; 원본 삭제를 이유로 자동 삭제·내용 재작성 금지 |

브라우저 바인딩은 불변이므로 정리를 위해 User의 연결을 임의로 NULL로 바꾸지 않는다. 만료된 판정 기록과 삭제 가능한 비참조 방문을 먼저 정리한 뒤, 키·캐시의 역참조를 같은 잠금 규약으로 재확인한다. 장기 보존 콘텐츠의 작성 방문이 키를 계속 참조하면 그 키도 보존한다. 이를 해제하거나 익명화하려면 별도의 보존·식별 정책을 명시해야 한다.

물리 FK가 없다는 이유로 직접 DELETE를 허용하지 않는다. 소속 댓글·스냅샷·최신 포인터 등 살아 있는 논리 관계가 남으면 부모의 물리 삭제를 거부한다. 별도 증거 키는 원본이 없어도 유지하고 다른 행에 재연결하지 않는다. 삭제된 숫자 ID·객체 키는 재사용하지 않는다.

## 대량 작업과 정합성 점검

대량 입력·정리도 동일한 검증과 잠금 계약을 적용한다. 안정된 ID 기준 커서로 처리 범위를 나누고, 작은 묶음·짧은 트랜잭션·중단 후 재시작 가능한 체크포인트를 사용한다. 자식 우선 정리가 필요한 경우 명시적으로 순서를 정하고, 다음 부모 삭제 직전에 역참조를 재검증한다. 임의 FK 검사 비활성화나 검증 없는 INSERT·DELETE는 사용하지 않는다.

참조 검색은 명시적 인덱스와 필요한 컬럼만 사용하며 `SELECT *`를 금지한다. 관계 인덱스는 Prisma의 자동 FK 인덱스에 의존하지 않는다. [조회 계약](query-contracts.md)을 함께 적용한다.

| 점검 | 판단 기준 |
| --- | --- |
| 일반 참조 | 존재하지 않는 작성 방문·소속 포스트·부모 댓글·스냅샷 소유자 |
| 복합 참조 | 부모의 postId 불일치, currentSnapshot 소유 ID 불일치 |
| 콘텐츠 완결성 | 스냅샷 없음, 최신 포인터 없음·최대 revision 불일치, 관리 키 누락 |
| 방문 바인딩 | 판정과 User의 키 불일치, 존재하지 않는 키·캐시 참조 |
| 역사적 증거 | JSON·투영 키의 내부 계약만 점검; 원본 부재·만료를 곧바로 고아 오류로 취급하지 않음 |

주기 점검은 동기 검증의 대체 수단이 아니다. 변경 중인 콘텐츠는 같은 루트 잠금 아래 최종 확인해 일시 상태를 오류로 오판하지 않는다. 이상 데이터는 기록·격리·승인된 복구 대상으로 분류하며 자동 삭제·작성자 추정·재연결·스냅샷 재작성은 하지 않는다.

향후 서버·샤드가 분리되면 단일 DB 트랜잭션과 행 잠금을 그대로 적용할 수 없다. 분산된 참조의 소유 서비스·승인·실패 보상 계약이 별도로 필요하며, FK를 없앤 현재 설계만으로 분산 정합성이 보장되지는 않는다.
