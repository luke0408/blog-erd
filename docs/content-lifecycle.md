# 콘텐츠 생성·수정·삭제

관련 구조: [포스트](../erd.md#posts), [포스트 정본](../erd.md#post_snapshots), [댓글](../erd.md#comments), [댓글 정본](../erd.md#comment_snapshots). 이미지 형식은 [데이터 계약](data-contracts.md#images), 조회 정책은 [조회 계약](query-contracts.md), 관계 검증과 삭제 경합은 [관계 무결성](relation-integrity.md)을 참조한다.

## 정본과 제약

본문·제목·이미지는 [포스트 스냅샷](../erd.md#post_snapshots)에 저장한다.
일반 조회는 currentSnapshot을 읽고 생성 시각이나 MAX(id)로 최신 정본을 추측하지 않는다.

- snapshots는 수정 이력 1:N이다. 커밋 시 최소 한 개의 스냅샷이 필요하다.
- currentSnapshot은 최신 정본 1:1이다. nullable은 생성 트랜잭션의 임시 상태를 허용한다.
- (id, currentSnapshotId)는 복합 논리 관계다. 다른 포스트의 스냅샷을 참조하지 않도록 서비스가 소유자를 검증한다.
- 서비스는 커밋 전에 포인터·최대 revision·콘텐츠 관리 키를 확인한다. 물리 FK나 지연 제약에 의존하지 않는다.
- 최초 작성자·발급 관리 키·생성 시각은 불변이다. DELETED 콘텐츠는 다시 수정하지 않는다.

## 생성·수정·삭제

| 작업 | 저장 순서와 기준 |
| --- | --- |
| 생성 | 메타데이터, revision 1 스냅샷, 최신 포인터, 생성 이벤트를 같은 트랜잭션에 저장 |
| 수정 | 관리 키 검증 후 행 잠금과 expectedVersion 비교, 새 스냅샷·포인터·version·이벤트 갱신 |
| 상태 변경 | version을 1 증가시키고 상태 변경 이벤트 기록 |
| 삭제 | DELETED로 전환, 스냅샷·신고·이미지 보존 |

최초 포인터 설정은 version=1을 유지한다. 이후 변경마다 version을 1 증가시킨다.
expectedVersion 불일치는 충돌로 처리하며 자동 덮어쓰지 않는다.
수정 세션은 새 스냅샷의 editorKey에 기록하고 최초 authorId는 바꾸지 않는다.

## 콘텐츠 관리 키

각 포스트·댓글에는 독립적인 256-bit 난수 관리 키가 있다. DB에는 SHA-256 해시만 저장한다.
수정·삭제는 현재 유효한 비회원 세션과 해당 콘텐츠의 관리 키를 함께 요구한다.
포스트 키로 타인의 댓글을 관리할 수 없다.

관리 키 원문은 URL·이벤트·이미지 메타데이터·로그에 넣지 않는다.
비밀 비교는 constant-time으로 수행한다. 키 유실 시 이메일·IP·별명으로 자동 복구하지 않는다.
관리 키는 콘텐츠 관리 권한이며 신고 집계용 동일인 식별자가 아니다.

서비스는 스냅샷 소유자 일치·불변성·버전·관리 키·관리자 권한을 검증한다. Prisma 논리 관계 선언만으로 DB가 이를 보장하지 않는다.
DB 계정 권한은 [저장 정책](storage-policy.md)을 따른다.

## 댓글과 대댓글

parentId가 NULL이면 일반 댓글, 값이 있으면 대댓글이다.
(parentId, postId)는 복합 논리 관계이며 서비스가 부모와 자식의 포스트 일치를 검증한다.
자기 자신을 부모로 둘 수 없으며, 소속 포스트와 부모는 생성 후 변경할 수 없다.

| 작업 | 기준 |
| --- | --- |
| 생성 | 존재하는 부모만 참조, 최초 authorId 고정 |
| 수정 | 관리 키와 version 검증, 새 CommentSnapshot 생성 |
| 최신 정본 | 포인터는 같은 댓글의 최대 revision을 참조 |
| 삭제 | DELETED 상태 전환, 정본·신고 증거 보존 |
| 노출 | 포스트 숨김은 댓글 노출도 차단 |
| 부모 숨김 | 본문 없는 자리표시자로 답글 구조 유지 |

최초 작성 세션과 실제 수정 세션은 구분한다.
콘텐츠 관리 키·스냅샷·동시성 규칙은 [포스트](../erd.md#posts)와 같다.

## 이미지 보존과 노출

객체 키·버전은 재사용하거나 덮어쓰지 않는다.
새 스냅샷에서 제외한 이미지도 과거 스냅샷이나 신고 증거가 참조하면 보존한다.
중복·실패 업로드 정리는 모든 스냅샷·신고 참조를 확인한 후 처리한다.

일반 조회에는 최신 허용 스냅샷의 이미지만 제공한다.
과거 이미지는 검수자나 해당 콘텐츠 관리 키 권한자가 조회한다.
포스트 숨김을 공개 버킷이나 장기 서명 URL로 우회하지 않는다.

## 원자성과 실패 처리

생성은 메타데이터 → revision 1 정본 → 최신 포인터 → 생성 이벤트 순서로 한 트랜잭션에 저장한다. 포인터의 대상 정본을 먼저 만들고 커밋 전에 관리 키·참조 존재·소유자·최소 정본·최대 revision 포인터를 서비스가 검증한다. 실패하면 전체를 롤백한다.

수정은 해당 콘텐츠 메타데이터를 잠그고 expectedVersion을 비교한 뒤 새 정본과 포인터·버전·이벤트를 함께 저장한다. 다른 방문의 관리 키 접근은 최초 authorId를 바꾸지 않으며 실제 수정 세션을 editorKey에 기록한다. 버전 불일치는 충돌로 거부하고 자동 덮어쓰지 않는다.

스냅샷 UPDATE·DELETE와 삭제된 콘텐츠의 재수정은 서비스가 거부한다. 댓글 재배치·자기 부모 참조는 금지하고 기존 같은 포스트의 부모만 선택한다. 상태 전이의 실패도 정본·이벤트 일부만 남기지 않는다.
