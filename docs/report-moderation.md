# 신고 접수·숨김·검수

관련 구조: [신고](../erd.md#reports), [포스트 정본](../erd.md#post_snapshots), [댓글 정본](../erd.md#comment_snapshots), [이벤트](../erd.md#outbox_events). 증거 형식과 투영 키 일치는 [JSON 데이터 계약](data-contracts.md#report-payload)을 따른다.

## 신고 수락과 보존

1. 클라이언트가 대상·사유·관찰 스냅샷의 서명된 조회 증표를 제출한다.
2. 서비스가 증표의 방문·대상·스냅샷·만료와 현재 세션 권한을 검증한다.
3. 정본 스냅샷을 읽어 서버가 증거 JSON을 구성한다. 클라이언트의 본문 사본은 신뢰하지 않는다.
4. Report와 OutboxEvent를 같은 짧은 트랜잭션에 저장한다.

신고 도중 콘텐츠가 수정되어도 사용자가 관찰한 스냅샷을 보존한다.
(reporterKey, targetKey, snapshotKey) UNIQUE로 동일 세션·대상·스냅샷의 중복 신고를 막는다.
같은 eventId의 다른 본문은 서비스에서 충돌로 거부한다.

증거·대상 투영 키는 불변이고 Report DELETE는 금지한다.
원본은 논리 삭제이며 스냅샷도 보존한다. 증거가 남아 있다고 일반 사용자에게 숨김 콘텐츠를 노출하지 않는다.

## 개인 숨김과 전체 숨김

| 구분 | 조건·효과 |
| --- | --- |
| 개인 숨김 | 현재 reporterKey의 대상 신고가 있으면 즉시 적용 |
| 개인 숨김 유지 | 기각·스냅샷 수정 후에도 유지, 새 방문으로 승계하지 않음 |
| 전체 집계 | targetKey별 서로 다른 reporterKey 수 |
| 집계 대상 | 서버 검증 후 수락한 status=PENDING 신고 |
| 전체 임시 숨김 | 5개 세션 이상이면 VISIBLE에서 PENDING_REVIEW로 전환 |

같은 세션의 여러 revision 신고는 전체 임계값에 한 번만 포함한다.
포스트와 댓글 신고는 합산하지 않는다. 수락 후 세션 만료는 신고를 취소하지 않는다.
5개 세션은 실제 사람 5명을 증명하지 않는다.

일반 읽기는 현재 집계를 검사해 워커 지연 중에도 임계값 이상 콘텐츠를 노출하지 않는다.
이 기준은 상세·목록·개수·검색·이미지에 동일하게 적용한다.
숨긴 포스트의 댓글도 차단하고, 숨긴 댓글은 본문 없는 자리표시자를 사용한다.

## 검수와 조회

검수는 별도 운영 인증 주체의 책임이다. 비회원 User를 관리자로 취급하지 않는다.
PENDING에서 CONFIRMED 또는 REJECTED로만 종료하며 version을 1 증가시킨다.
검수 결과·reviewedAt·상태 변경 이벤트를 함께 기록하고 증거 본문은 바꾸지 않는다.

목록·검색·정렬은 [조회 계약](query-contracts.md)을 따른다.
작성 세션 키·IP 일치는 실제 동일인 증명이 아니며 신고 악용 제어는 서비스의 책임이다.

접수는 신고와 이벤트만 저장하고 원본의 신고 카운터를 매번 갱신하지 않는다.
테이블 분리는 쓰기 책임을 분리하지만 같은 DB의 CPU·I/O·연결 풀을 완전히 격리하지는 않는다.

증표는 현재 방문·대상·관찰 정본·만료에 바인딩한다. 검수 이후 완료 검수를 다시 쓰지 않는다. 세션 재발급은 다른 신고 세션이며 이를 동일인으로 자동 병합하지 않는다.
